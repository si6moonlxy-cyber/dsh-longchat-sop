# 长会话保真压缩 · 标准流程（SOP）

> 适用：DSH 中导入/迁移的几百轮长会话。
> 目标：压缩后还能接着用，关键信息不丢；且流程可循环、可批量、可验收。

## 0. 三层模型

| 层 | 内容 | 性质 | 存放 |
|---|---|---|---|
| L0 归档 | 原始 session 文件 + 可读 Markdown + 附件 | 无损、只读 | `work/dsh-archive/<日期>/` |
| L1 索引 | 主题索引（时间线 + 主题 + 结论） | 有损、粗 | `INDEX.md` / 会话摘要 |
| L2 细节 | 分主题中文摘要（带 seq 出处、关键原话） | 有损、细 | `digest.md` / 临床笔记 |
| L3 种子 | 新会话首条消息（L1+L2 合成） | 用于继续对话 | 新会话 |

一句话：**保真在 L0，压缩只在 L1/L2；L3 用来继续，不替代 L0。**

## 0. 交付形态（默认）：原会话原地压缩

**标准交付 = 同一个会话（同一个 session-id）在原地被压缩，客户接着原对话继续聊。**

- 不做“新开一个没有上下文的会话”；
- 新会话 / seed 只在两种场景用：① 跨设备/跨 DSH 迁移；② 原会话已损坏或无法继续；
- 压缩的产物必须仍挂在原工作区、原标题、原时间线上，客户打开就能接着说话。

> 这也决定了技术路线：优先用 DSH 的**原地压缩**（`/compact` 或自定义 compaction engine），而不是“导出摘要再开新会话”。

## 1. 领域判定（先做这一步）

| 领域 | 判据 | 策略 |
|---|---|---|
| 学习/资料 | 一问一答、查资料、备考 | **不需要超长上下文时直接 `/compact`**；要细节就加主题索引 |
| 心理咨询 | 情绪、关系、危机语句 | **禁止通用压缩**；原文归档 + 中文临床笔记 |
| 角色扮演/情感陪伴/对话模拟 | 人设、关系线、台词、梗 | **禁止通用压缩**；人设卡 + 关系线 + 台词/梗库 + 雷区（见 `templates/roleplay-note.md`），原文单独归档 |
| 代码/项目 | 改文件、跑命令、报错 | 中等压缩；保留路径、命令、错误原文 |

**咨询类红线**：不压原话、不压风险信息、不转英文、不并用两个 AI 的结论。

## 2. 盘点

用 `session_projcache` 的 `contextPressure.surfaceTokens` 分档：

| 档 | tokens | 处理 |
|---|---|---|
| 小 | <100k | 只归档 |
| 中 | 100–300k | 轻压（`retainTokens: 65536`） |
| 大 | >300k | 重压（`retainTokens: 32768`）或只归档 |

输出：`session-id / 标题 / 工作区 / tokens / 领域 / 是否继续`。

## 3. 归档（不可跳过）

1. 冷备份会话目录（含 v3/v4 文件）；
2. 解压 JSONL（`decompress-session.cjs`）；
3. 导出 Markdown（`export-markdown.cjs`，会过滤运行时/记忆注入噪声）；
4. 附件按 hash 拷贝；
5. 写 `manifest.json`（id/标题/tokens/时间/文件/附件）。

## 4. 压缩（仅学习/代码类）

桌面 profile 的 `compaction-basic` 配置：

```yaml
- id: compaction-basic
  name: '@deepseek-ai/dsh-compaction-basic'
  config:
    retainTokens: 32768     # 最近只保留约 3.2 万 token 原文
    thresholdRatio: 0.5     # 自动压缩从 80% 提前到 50%
```

重启后，在会话里输入 `/compact`（空闲时），重复到提示没有可压缩历史。

> 注意：`/compact` 每次只压“保留尾巴之前”的那一段；若最近有单条超大消息，尾巴会吃掉预算，一次能压的很少。

## 5. 保真校验

- 摘要 8 段是否齐全（Primary Request / Key Concepts / Files / Errors / Pending / Current Work / Next Step / Critical Context）；
- 关键词抽查：原会话的高频实体（人、项目、数字、路径）在摘要里是否出现；
- 咨询类：风险语句、原话、时间线必须逐条核对，不得只依赖摘要。

工具：`check-compact.cjs`。

## 6. 咨询类：临床笔记（替代压缩）

模板见 `templates/clinical-note.md`，最少包含：

- 来访者画像（稳定事实，谨慎更新）
- 本次会谈：主诉 / 情绪曲线 / 关键原话（引用）/ 干预
- 风险与安全（不可压缩，保留原话与时间）
- 模式与假设（标注“假设”）
- 作业与下次方向
- 禁忌与提醒

规则：
1. **原文不压**，只写笔记；
2. 笔记用中文，保留语气与原话；
3. 风险信息永远保留原文；
4. 新会话用笔记做种子，不贴全文；
5. 归档只放 Psyche 工作区，不进公共包。

## 6b. 角色扮演 / 情感陪伴：人设与关系笔记

通用压缩会丢：人设语气、称呼、口头禅、表情习惯、关系里程碑、梗与禁忌——这些恰恰是这类会话的全部价值。

- **原地压缩时的保真做法**：压缩前先在原会话里生成一份中文「关系/人设快照」发到对话里，让它落在保留尾巴内；再 `/compact` 压掉更早的历史。这样客户继续原会话时，模型仍能看到完整的人设与关系锚点。
- 备用：`templates/roleplay-note.md`（仅迁移/备份时用）。
- 原文另行私密归档，不进公共包。
- 更新节奏：每 1–2 周，或关系状态变化时。

## 6c. 咨询类原地压缩（不新开会话）

- 先让模型在原会话里产出一份**中文临床笔记**（本 SOP 的模板），作为一条消息留在会话尾部；
- 再执行 `/compact`（`retainTokens` 设为能保住这条笔记的大小）；
- 结果：原会话继续可用，且最新的中文笔记在保留尾巴里，不会被英文摘要覆盖。

## 7. 归档与上手机

- zip：`sessions/` + `markdown/` + `manifest.json` + `INDEX.md`
- 手机先看 `INDEX.md`；要查阅用 `markdown/`
- 要继续对话：DSH Go 用 remote 模式连接电脑（比导入会话稳），或用 L3 种子在新会话继续

## 8. 批量策略

- 不要手点几百次 `/compact`（每次一次模型调用，成本高）；
- 批量流水线：导出 Markdown → 分片 → 子代理并行生成 L2 摘要 → 合并 INDEX；
- 每批 20–30 个，抽查 3 个再继续；
- 只对 A 类（要继续）做 DSH 压缩，B/C 类只归档。

## 9. 验收记录（2026-11-18，杂论）

- 压缩前：1,076 条消息 / 515,662 tokens / 1,250,436 字符
- `/compact`：1,615 条 / 515,040 tokens；压缩后表面 2,308 tokens
- 摘要：6,334 字符，8/8 段，英文
- 关键词 12 个：保留 6、丢失 6
- 结论：合格作为“索引”，不合格作为“保真压缩”
