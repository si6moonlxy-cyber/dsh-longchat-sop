# 给 GPT 的提示词：生成客户版 Word 教程

> 用法：把下面整段复制给 GPT（或 Claude），让它输出 Markdown，再粘进 Word 套样式。

---

你是资深技术文档工程师。请为「**DSH 长会话保真压缩与迁移服务**」写一份**客户交付版 Word 教程**，读者是非技术客户（会基本电脑/手机操作，但不了解 DSH 内部机制）。

## 写作目标

让客户按文档能独立完成这条流水线：

> 从 DeepSeek 网页/App 导出会话 → 导入官方 DSH → 归档无用会话 → 对有用会话做**原会话原地压缩**（不新开会话）→ 打包迁移到 DSH Go（手机）→ 验收交付。

## 硬性要求

1. 全部中文；步骤编号；每一步写清「目的 / 操作 / 预期结果 / 失败怎么办」。
2. 输出 **Markdown**（`#`/`##`/`###`、表格、代码块、清单），便于直接转 Word；不要输出 HTML。
3. 不要编造产品能力；不确定的地方写「以实际界面为准」。
4. **不要出现任何真实个人信息、真实路径、API Key、账号、聊天内容**；示例统一用占位符：`<DSH_HOME>`、`<工作区路径>`、`<会话ID>`、`<zip 路径>`、`客户A`。
5. 需要截图的位置写成 `[截图：说明要截什么]`。
6. 篇幅约 15–25 页（Word 计），语言简洁、可执行。
7. 增加「服务边界与隐私」章节：说明压缩是有损摘要、原文归档才是保真依据；咨询类内容单独归档、不外发；客户需自行确认数据授权。

## 必须覆盖的事实

- **概念区分**：DSH（桌面/服务端）与 DSH Go（Android 客户端，本地模式或 remote 模式）。
- **压缩原理**：压缩时保留最近约 16% 窗口原文，其余替换为一份 checkpoint 摘要；`/compact` 每次只压「保留尾巴之前」的一段；自动压缩默认开启，可能在请求前插入。
- **中文压缩引擎**：安装 `compaction-zh` bundle 后，压缩指令变为中文、分领域模板，输出八节结构（这段对话是什么 / 用户画像 / 时间线 / 关键原话 / 风险与安全 / 模式与假设 / 未决与下一步 / 语气与人设），自动与手动压缩都生效，会话 id 不变。
- **领域策略**（表格）：
  - 学习/资料：可直接 `/compact`，或补主题索引；
  - 情感咨询/陪伴：禁止通用压缩，用中文引擎并保留风险原话；
  - 角色扮演/人设对话：保留人设、称呼、语气、口头禅、关系线、梗与禁忌；
  - 代码/项目：保留文件路径、命令、错误原文。
- **工具链**：
  - `pack-sessions`：桌面端按工作区打包 zip；
  - `session-import`：DSH/DSH Go 安装后提供 `import_sessions` 工具（支持 `dryRun`）；
  - zip 结构：`manifest.json` + `sessions/<workspace-key>/<session-id>/session.v3|v4.jsonl.zstd`。
- **工作区目录键规则**：`D:\Project_Mine\Agent` → `--D-Project_Mine-Agent--`（盘符后的 `:\` 合并为一个 `-`），空格 → `~0020`；打包与导入必须一致，否则“导入了但看不见”。
- **常见坑**（写成“排错”表格）：自动压缩抢跑；改 `contextWindow` 不改变阈值；v3/v4 格式差异；zip 误带本地备份；导入后需重启刷新。
- **验收清单**：会话 id 不变、能继续对话；摘要为中文八节；关键原话/数字/日期/路径保留；咨询类风险语句逐字保留；导入后侧栏可见；归档 zip 可回查。

## 文档结构（按此顺序）

1. 封面（服务名、版本、日期、客户名占位）
2. 版本记录
3. 目录
4. 服务说明（做什么、不做什么、交付物清单）
5. 术语表（DSH / DSH Go / 会话 / 工作区 / checkpoint / compaction / bundle）
6. 前置条件（环境、权限、备份、隐私授权）
7. 总体流程图（用文字/表格画：下载 → 导入 → 归档 → 压缩 → 打包 → 手机导入 → 验收）
8. 桌面端操作（分步）
   - 8.1 导入会话
   - 8.2 归档无用会话
   - 8.3 安装中文压缩引擎
   - 8.4 原会话压缩（先笔记后压缩 / 自动压缩的注意点）
9. 打包与迁移（分步）
   - 9.1 打包 zip
   - 9.2 传到手机
   - 9.3 DSH Go 安装导入器
   - 9.4 执行导入（dryRun → 正式）
   - 9.5 重启与验证
10. 领域策略（四类会话的差异化处理，表格）
11. 验收清单（可勾选）
12. 常见问题与排错（表格：现象 / 原因 / 处理）
13. 服务边界与隐私
14. 附录
   - A. 命令速查
   - B. zip 结构示例
   - C. 临床笔记模板（咨询类）
   - D. 人设/关系笔记模板（角色扮演类）
   - E. 一页速查卡

## 语气

专业、克制、面向客户；不用营销夸张词；不暴露内部实现细节（如源码路径、内部插件名可保留但不必展开）。
